# W16 Spot-Check Sample — 2026-08-30

Generated by `scripts/spot_check_sample.py --seed 16` from `artifacts/index.json` (25273 servers scored, 821 flagged) on 2026-08-30.

Purpose: hand-verify a representative sample of mcphound's real registry-scan output before publishing scores — see ROADMAP.md's W16 credibility gate.

**Sampling methodology:**
- All 4 server(s) flagged by the rare rules (`MCP-STATIC-003`/`004`) — too few to subsample, and the highest-value ones to check by hand.
- 31 random server(s) (seed=16) out of 817 servers flagged only by `MCP-STATIC-007` (missing npm `repository` field) — the bulk of flagged servers, and the main false-positive risk.
- 15 random server(s) (seed=16) from the 24452 clean (score-100) servers — a false-negative check: did we miss something real?

Reproducible as long as `artifacts/index.json`/`artifacts/servers/` don't change between runs — the sample is a deterministic function of the seed and that data.

## Result (2026-08-30 review)

All 50 servers reviewed by hand against live sources (the MCP registry API, npm/PyPI registries, and GitHub) — see the verdict table and per-server notes below for the evidence behind each row.

- **0 false positives, 0 false negatives.** All 4 rare-rule (`MCP-STATIC-003`/`004`) findings and all 31 `MCP-STATIC-007` findings checked out against live registry/npm data. None of the 15 clean servers showed a missed detection.
- **1 uncertain**, worth a follow-up: `io.github.SamYuan1990/i18n-agent-action` (clean, score 100) launches an OCI image via a floating `:mcp` tag rather than a pinned semver version — not literally `@latest`, so `MCP-STATIC-004` doesn't catch it. Possible detection gap in how that rule handles OCI tags; not fixed as part of this review.
- **1 message-accuracy gap in `MCP-STATIC-007`**: 3 of the 31 sampled servers (`ai.dinglebear/apprise-rmcp`, `ai.dinglebear/tailscale-rmcp`, `ai.marketintell/marketintell`) had npm packages that were fully **unpublished** before the scan ran, not merely missing a `repository` field. The finding's technical claim is still true in a degenerate sense (the tombstone record has no repository field either), but the message ("no repository field in its registry metadata") understates what's actually going on — an unpublished package is a more significant signal than missing metadata, and current wording doesn't distinguish the two. Worth a follow-up rule tweak, not a correctness bug.
- **Sampling note**: 7 of the 31 `MCP-STATIC-007` samples came from one publisher (`@codespar/*`) — random chance, not a stratification bug, but worth knowing the sample wasn't 31 independent publishers.
- **Scope note**: 8 of the 15 clean samples are remote (`streamable-http`) servers with no local launch command at all — their score of 100 reflects being out of mcphound's current static-scan scope (remote deep-scan is roadmapped for v1.2), not a verified-safe command.

**Credibility gate verdict: pass.** No evidence found that published scores misrepresent what mcphound's rules actually detected in the real launch configs. The two follow-ups above are rule-quality improvements, not retractions.
